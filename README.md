# Deep3DRadon 

**Starting point for Research Project 2026**

Deep3DRadon is a hybrid C++/Python framework designed to automate the absolute calibration of the Pattern Center (PC) for High Angular Resolution EBSD (HR-EBSD). 

## Project Architecture

The workflow is divided into two main components:
1. **C++ Pipeline (Data Generation):** Simulates simplified wire-type EBSD patterns (kinematic hyperbolas) and extracts local 3D Radon sub-volumes around specific crystallographic peaks.
2. **Python Pipeline (Deep Learning):** Trains a multimodal 3D-CNN to map morphological distortions in the Radon space directly to a 3D spatial correction vector ($\Delta VP$).

---

## Part 1: C++ Data Generation


### What it does
- Simulates EBSD patterns for varying crystal orientations.
- Applies a controlled geometric shift (e.g., 1%) to the View Point (VP) to simulate PC misalignment.
- Targets 25 specific crystallographic reflectors per pattern.
- Computes a local $16 \times 16 \times 16$ voxel 3D Radon Transform box centered on each peak's theoretical normal.

## Part 2: Python Deep Learning Pipeline

The Python pipeline is built with **PyTorch**. It handles the ingestion of binary data generated by the C++ code, the multimodal fusion of geometric metadata, and the training of the 3D-CNN.

### 1. Data Management (`dataset.py`)
The `RadonDataset` class is designed for memory-efficient loading and dynamic preprocessing:
- **Binary Parsing:** Reads `double` (float64) values from C++ `.bin` files and converts them to `float32` tensors.
- **Dynamic Reshaping:** Automatically detects the number of crystallographic planes from the CSV headers to reshape volumes into `(nb_planes, 16, 16, 16)`.
- **Normalization:** - **Inputs:** Local Min-Max normalization for each Radon volume to handle intensity variations.
  - **Targets:** Z-score normalization (mean/std) for the ViewPoint (VP) coordinates to ensure stable convergence.
- **Multimodal Output:** Returns a dictionary containing the Radon cubes, the plane normal vectors (physical context), and the simulation increment.

### 2. Model Architecture (`model_architecture.py`)
The **RadonCNN3D** model uses a multimodal fusion approach to combine visual and geometric information:
- **3D-CNN Branch:** Three layers of 3D convolutions with Batch Normalization and Max-Pooling to extract morphological features from the Radon peaks.
- **Contextual MLP:** A sub-network that processes the "where" (normal vectors) and the "scale" (increment) of the capture.
- **Fusion Layer:** Concatenates the flattened visual features (2048 dims) with the contextual vector (64 dims).
- **Regression Head:** Fully connected layers with Dropout (0.4 and 0.3) to predict the 3D correction vector $(\Delta VP_x, \Delta VP_y, \Delta VP_z)$.

### 3. Training & Optimization (`train.py`)
The training script orchestrates the learning process:
- **Loss Function:** Mean Squared Error (MSE) adapted for regression.
- **Optimizer:** Adam optimizer with an initial learning rate of `0.0005`.
- **Learning Rate Scheduler:** Uses `ReduceLROnPlateau` to halve the learning rate if the validation loss stagnates for 5 epochs.
- **Safety Features:** - Automated detection of CUDA (GPU) for acceleration.
  - Best-model saving: The script monitors validation loss and saves the state dict to `models/radon_cnn_best.pth`.

## Part 3: Future Roadmap - Autonomous Inference & Predicting Normals

The current POC relies on knowing the exact theoretical normals of the crystallographic planes to feed the `Contextual MLP`. The ultimate goal for the industrial transition is to achieve **Fully Autonomous Inference**: the model should only receive the raw 3D Radon boxes (or standard patterns) and simultaneously deduce both the **Pattern Center (VP shift)** and the **Crystal Orientation (Plane Normals)**.

### 1. Architectural Shifts
To achieve this, the architecture must transition from using normals as *inputs* to producing them as *outputs*:
- **Input:** $N \times 16^3$ Radon boxes (+ the scale increment).
- **Multi-Task Output Head:** - **Head A (Spatial):** Predicts the 3 values for the ViewPoint shift ($\Delta VP_x, \Delta VP_y, \Delta VP_z$).
  - **Head B (Angular):** Predicts the crystallographic orientation.

### 2. Loss Function Strategy
Training a multi-task network requires a composite loss function. We must balance two completely different physical quantities: spatial translations (VP) and angular rotations (Normals).

- **VP Loss ($\mathcal{L}_{VP}$):** Standard Mean Squared Error (MSE), as currently implemented.
- **Normals Loss ($\mathcal{L}_{Normals}$):** As suggested by C. Maurice, this should be an **Angular Deviation Loss**. Instead of standard MSE on coordinates, we calculate the angle between the predicted normal $\hat{n}_{pred}$ and the true normal $\hat{n}_{true}$ using the dot product (Cosine Similarity):
  $$\mathcal{L}_{Normals} = \frac{1}{N} \sum_{i=1}^{N} \left(1 - \frac{\hat{n}_{pred}^{(i)} \cdot \hat{n}_{true}^{(i)}}{||\hat{n}_{pred}^{(i)}|| \cdot ||\hat{n}_{true}^{(i)}||}\right)$$
- **Total Loss:** $\mathcal{L}_{Total} = \lambda_1 \mathcal{L}_{VP} + \lambda_2 \mathcal{L}_{Normals}$
  *Note: The weighting factors ($\lambda_1, \lambda_2$) will be hyper-critical. If one loss is numerically much larger than the other, the network will ignore the smaller one.*

### 3. Critical Reflections & Anticipated Roadblocks ⚠️

Moving to this autonomous setup introduces several deep technical challenges that must be addressed:

#### A. The Ambiguity Problem (PC Shift vs. Crystal Rotation)
This is the fundamental physical limit of EBSD: shifting the Pattern Center and physically rotating the crystal can produce nearly identical morphological distortions on the Kikuchi bands. By asking the network to predict *both* simultaneously, we risk introducing a highly non-convex loss landscape where the AI constantly hesitates between "Did the PC move?" and "Is the grain tilted?". The model will need a massive, highly diversified dataset to learn to decouple these two phenomena.

#### B. The Degrees of Freedom Trap (75 outputs vs. 3 outputs)
We target 25 planes. Predicting 25 independent normal vectors means outputting 75 values. However, a rigid crystal lattice only has **3 degrees of freedom** (orientation in 3D space). 
* **The Risk:** If the network predicts 25 independent normal vectors, it will likely break the rigid physical structure of the crystal (the interplanar angles will be wrong).
* **The Solution:** Instead of predicting 25 independent normals, the network should predict the global crystal orientation (e.g., a **Quaternion**, 4 values). The 25 specific normals can then be deterministically calculated from this single predicted orientation using standard rotation matrices. This mathematically forces the network to respect the crystal physics.

#### C. L2 Normalization Enforcement
If we stick to predicting vectors, neural networks do not naturally output unit vectors (length = 1). An $L_2$ Normalization layer (`torch.nn.functional.normalize`) must be strictly applied to the output of the normals branch before calculating the angular loss, otherwise the dot-product mathematics will fail.

#### D. Implementation Sketch: Multi-Task Architecture
To help kickstart the autonomous transition, here is a conceptual Python draft for a multi-task trainer:
```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class AutonomousRadonCNN(nn.Module):
    def __init__(self, num_planes=25):
        super().__init__()
        # Shared Feature Extractor (Encoder)
        self.encoder = nn.Sequential(
            nn.Conv3d(num_planes, 64, kernel_size=3),
            nn.ReLU(),
            nn.Flatten()
        )
        
        # Head A: Spatial Correction (VP Shift)
        self.vp_head = nn.Linear(2048, 3)
        
        # Head B: Orientation (Quaternion)
        self.quat_head = nn.Linear(2048, 4)

    def forward(self, x):
        features = self.encoder(x)
        
        vp_shift = self.vp_head(features)
        
        # Enforce unit quaternion (Normalization)
        quat = self.quat_head(features)
        quat = F.normalize(quat, p=2, dim=1) 
        
        return vp_shift, quat

def multi_task_loss(pred_vp, pred_quat, target_vp, target_quat, l1=1.0, l2=0.5):
    # Loss 1: Spatial MSE
    loss_vp = F.mse_loss(pred_vp, target_vp)
    
    # Loss 2: Angular Distance (1 - Cosine Similarity)
    # Using dot product for quaternions as a proxy for orientation error
    inner_product = torch.sum(pred_quat * target_quat, dim=1)
    loss_quat = torch.mean(1 - inner_product**2) 
    
    return l1 * loss_vp + l2 * loss_quat
```


### **Understanding the Multi-Task Sketch**

This code prototype illustrates the transition from an **assisted** model (which receives normals as input) to an **autonomous** model (which deduces them). Here are the three main pillars of this approach:

* **Shared Feature Extraction (Shared Encoder):** Instead of having two separate models, a single "trunk" (the 3D-CNN encoder) is used. The network learns to create a universal feature space where the morphological distortions of the Radon signal encode both the spatial position and the crystal orientation. This is where the network learns to **"decouple"** the effects of the Pattern Center from those of the crystal rotation.

* **The Quaternion Strategy (Orientation vs. Normals):** Rather than predicting 75 independent coordinates for the 25 normals (which would break the rigid physical geometry of the crystal), the code predicts a **unit quaternion** (4 values). This approach mathematically guarantees that the diffraction lattice structure remains consistent: once the global orientation (quaternion) is predicted, the 25 specific normals can be recalculated by simply rotating a reference crystal. The `F.normalize` layer ensures that the quaternion remains physically valid (norm equals 1).

* **Multi-Task Loss Function (Hybrid Loss):** The `multi_task_loss` function is the "central nervous system" of the training process. It combines:
    1.  **Spatial Error ($\mathcal{L}_{VP}$)** in millimeters via standard MSE.
    2.  **Angular Error ($\mathcal{L}_{quat}$)** which measures the deviation between the predicted and true orientation.
    
    The use of the squared dot product ($inner\_product^2$) in the quaternion loss handles the **double cover** property of quaternions ($q$ and $-q$ represent the same rotation), ensuring stable convergence toward the correct orientation.
